# Web release

The public game is https://go2jd.taati.dev/. GitHub Actions publishes the committed `builds/web` directory; it does **not** compile Unity. A source-only push will not update the playable game.

## Build and validate

Use the Unity version in `hnp-game/ProjectSettings/ProjectVersion.txt`. Preserve/save the current scene before building. With the Editor closed, run:

```powershell
./tools/build-web.ps1
```

When building through the open Editor, use `HNP.Editor.HnpLatestWebBuild.Build()` and then run:

```powershell
./tools/prepare-web-release.ps1
```

This stamps each binary URL with its content hash and writes `builds/web/release.json`. Run the browser QA against this exact directory. Any subsequent Unity build requires stamping and relevant browser tests again. The deployment workflow checks the manifest against every canonical file and rejects stale/mixed artifacts.

## Publish and confirm

Commit the Unity sources/dependencies, approved art sources/exports, reports and canonical `builds/web` output. Keep Unity-generated caches and rejected/in-progress art out of the release. Push `main` after local checks pass.

After the Actions deployment succeeds:

```powershell
./tools/verify-web-release.ps1
```

The verifier checks the public HTML, data, JavaScript and WebAssembly against the tested SHA-256 values, including the Wasm MIME type. A hash match proves delivery, not gameplay: repeat the browser journey on the public URL and record its build ID. Keep physical-phone results separate from desktop and viewport-emulation results.

## Locked canonical output

If Windows prevents Unity from overwriting a mapped file in `builds/web`, do not publish the partially written failed build. Build into a fresh directory ending in `web`, verify its Unity build report says `Succeeded` with zero errors, then run `tools/promote-web-release.ps1 -Source builds/web-release-final/web`. Promotion checks every copied file and leaves identical files untouched; it then stamps the canonical release manifest. Run browser QA against the promoted `builds/web` before committing. `.gitattributes` preserves generated bytes so Git line-ending conversion cannot invalidate the tested hashes.
